Read those two blocks together, because they do not agree and the disagreement is the
interesting part. The query itself got roughly 27x faster. The HTTP request it sits inside
got about 2.1x faster. The difference is everything else in a request that was never the
index's fault: JWT validation, model binding, EF materialisation, JSON serialisation, and
the network hop. At this seed size the overlap query was a large part of the request but
never all of it, so Amdahl caps what one index can do end to end.

Doubling throughput on a single-line schema change is still the honest headline. Claiming
27x would not be: that number is real at the database, and it is not what a caller
experiences.

----------

answer instead of filtering to it:

    -> 23 rows, no heap filter, 0 rows removed
  28 buffers touched, 0.032 ms

Compare the before run: 2,454 rows found by the foreign-key index, 2,431 of them thrown
away by the heap filter, 2,453 buffers, 0.861 ms.
